# CrisisBench v0.4 — Dataset &amp; Data Card

> **CrisisBench**: 中文灾害态势推理与辅助决策的多智能体评测基准（A benchmark for multi-agent disaster situation reasoning and decision support in Chinese）。
>
> 本文件为评审期匿名发布数据卡（Anonymous release, v0.4）。数据集与脚本不含任何真实作者姓名、单位或 GitHub 用户名。

---

## 1. 概览 Overview

CrisisBench v0.4 包含 **36 个中文灾害决策场景**，用于评测（多）智能体在灾害态势下的**事实提取、因果推理与决策建议**能力。

核心统计（与 `scenarios/scenarios.json` 一致）：

| 指标 | 数值 |
|---|---|
| 场景数 | **36** |
| 类别分布 | 单灾种 **14** / 链式（次生灾害）**14** / 信息矛盾 **8** |
| 评分要点总数 | **709** |
| 数值推算型要点（`要点` 以"推算"开头） | **48** |
| 每个场景要点数 | 18–21（事实层 8–9 / 推理层 4–5 / 决策层 6–7） |
| 每个场景情报条数 | 9–11 |
| 每个场景资源条数 | 4–6 |
| 含"无X"否定资源的场景数 | 35 / 36 |

三层评分协议（事实层 Fact / 推理层 Reasoning / 决策层 Decision）定义于 `scenarios/rubric.md`，逐场景要点清单位于 `scenarios/scenarios.json` 中每个场景的 `rubric` 字段。

类别要点小计：单灾种 259、链式 283、信息矛盾 167（合计 709）。

## 3. 数据结构 Data schema

### 3.1 顶层对象（`scenarios.json`）

根对象包含两个字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `meta` | object | 元信息 |
| `scenarios` | array | 36 个场景对象 |

`meta` 的字段：

| 字段 | 说明 |
|---|---|
| `benchmark` | 基准名称与版本字符串（"CrisisBench v0.4（36 场景扩容版）"） |
| `语言` | 数据集语言（中文） |
| `标注人` | 标注人声明（声明初稿由 AI 助手代拟、投稿前需人工逐条审改；**匿名发布版不在此处出现任何真实姓名**） |
| `难度设计` | 难度设计说明（数值推算要点、干扰/矛盾情报、陷阱诱导的构造思路） |

### 3.2 场景对象（`scenarios[]`）

每个场景对象包含以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 场景编号，如 `S001`（`S001`–`S005` 为 v0.3 原版，`S006`–`S036` 为 v0.4 新增） |
| `类别` | string | 三大类之一：`单灾种` / `链式` / `信息矛盾` |
| `灾种` | string | 灾害类型（触发/主灾种名，见 §4 灾种清单） |
| `时间点` | string | 场景所处的灾害时间节点，如"震后5小时" |
| `情报` | string[] | 9 至 11 条多来源情报片段（通报 / 现场 / 社媒 / 气象），可含干扰、矛盾与错误处置诱导 |
| `资源` | string[] | 4 至 6 条可用资源清单，显式列出可用资源与"无X"否定项（如"无直升机"） |
| `rubric` | object | 三层评分要点，见 §3.3 |

### 3.3 评分要点（`scenarios[].rubric`）

`rubric` 为一个对象，含三个键：

| 键 | 说明 |
|---|---|
| `事实层` | 关键事实要素要点数组 |
| `推理层` | 因果结论要点数组 |
| `决策层` | 行动建议要点数组 |

要点数组中的每个要点对象：

| 字段 | 出现层 | 说明 |
|---|---|---|
| `要点` | 全部三层 | 要点文本。数值推算型要点以 **"推算"** 开头（回答须给出推算出的数值/区间；只复述情报原数字不算满足） |
| `match` | 全部三层 | 用于规则打分（关键词匹配自检）的关键词列表。评审/正式评测以 LLM 打分 + 人工抽检为准 |
| `起点` / `机制` / `终点` | 仅推理层 | 因果结构三要素，仅供人工核对与论文展示，**不作为** LLM 裁判逐字对号要求 |

### 4.2 灾种清单（JSON 中 `灾种` 字段的去重取值，共 26 种）

- **单灾种（14）**：洪涝、山火、泥石流、山洪、城市内涝、低温雨雪冰冻、粮库火灾、危化品泄漏、民房火灾、大风灾害、中毒、水库泄洪、坍塌、爆炸

### 4.3 附属文件统计（`experiments/verify_specs.json`）

Verifier 确定性校验规格覆盖全部 36 个场景：

| 规则类型 | 条目数 |
|---|---|
| `calc`（数值推算区间） | **49** 条（注：S021 有两条条目共用编号 `F8`，第二条 `1.5–1.7 吨` 疑应为 `F9`，为数据中的已知编号笔误） |
| `traps`（决策束缚：`contains` 命中且 `must_any` 无一命中即违规） | **18** 条 |
| `capacity`（运力/资源缺口） | **1** 条 |

> 说明：场景 JSON 中"推算"开头的评分要点为 48 条；`verify_specs.json` 的 `calc` 为 49 条，二者相差 1 源自上述 S021 重复编号（`1500–1700 公斤` 与 `1.5–1.7 吨` 为同一推算点的两种单位写法）。

## 5. 用途 Use cases

- **多智能体 / 单智能体灾害研判评测**：给定场景情报与资源，输出三层研判结论（事实 · 推理 · 决策），按三层 rubric 逐条 0/1 打分。
- **评分协议研究**：三裁判多数票（规则 + 双 LLM 裁判）协议、裁判一致性（一致率 / Cohen's kappa）报告。
- **约束校验组件研究**：`verify_specs.json` 提供资源超配、数值推算、情报冲突、陷阱处置的可确定化校验规则。
- **人类参照分**：`human-baseline/template.md` 提供作答模板，可用若干名同学作答同一批场景得到人类基线。

## 6. 局限与伦理 Limitations &amp; ethics

- 全部场景为**人工虚构**，不含任何真实个人信息与真实警情。
- 情报初稿**由 AI 助手代拟**，可能引入模板化措辞或隐蔽偏置；发布前须经人工逐条审改。
- **不得用于真实应急指挥/现场处置**。本基准面向辅助决策研究的评测，结论不构成现场处置依据，不替代人工指挥。
- 评测基于 checklist 式 0/1 判定，仅覆盖要点是否"说到"，不评估行动的实际可行性、资源协调细节与时效性。
