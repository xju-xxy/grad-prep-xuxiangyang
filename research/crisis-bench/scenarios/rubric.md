# CrisisBench 三层打分细则（Rubric）

> 版本：v0.1 试水版 · 配套数据：[scenarios.json](scenarios/scenarios.json)
> 本文件是论文"评测协议"章节的素材，评审和复现者都按这份规则打分。

## 一、总原则

1. **checklist 式判定**：每个要点独立判 0/1，不做程度评分（0.5 分不存在），保证可复现。
2. **采点不算错点**：只检查"该说的说了没有"，不惩罚无关内容（除非决策层出现**资源超配**，见§四）。
3. **同义算命中**：判定时允许同义替换（"撤离"="疏散"），以要点文本语义为准，不以字面为准。
4. **两句来源**：规则打分（关键词匹配）用于快速自检；**正式评测一律以 LLM 打分 + 人工抽检为准**（§六）。

## 二、事实层（Fact）

- **考什么**：智能体回答里有没有"捡全"该场景的关键情报要素。
- **怎么判**：逐条对照 rubric 里的"事实层"要点，回答提到即 1 分，未提到 0 分。
- **得分公式**：事实层得分 = 命中要点数 ÷ 总要点数。
- **注意**：信息矛盾场景（如 S005）中"识别到矛盾本身"也是一条要点——只说其中一个数字、没意识到两个数字打架，不得分。

## 三、推理层（Reasoning）

- **考什么**：因果链想没想对。
- **判定标准**：每条推理要点要求**起点-机制-终点**三要素齐全（见场景 JSON 中每条的三字段，为人工核对用；LLM 打分时直接依据要点文本判断回答是否完整覆盖该链条）：
  - 起点（拿到的事实）→ 机制（为什么会导致）→ 终点（推出什么后果/风险）。
  - 缺机制只喊口号（如只说"有溃坝风险"但没说"裂缝+降雨"为什么导致），不得分。
- **信息矛盾场景附加规则**：对矛盾的处理方式要"合理且说明依据"（采信哪个口径+为什么+留核查），只说"数据不一致需要注意"但无处理策略，得 0.5 处理为不得分（仍按 0/1）。

## 四、决策层（Decision）

- **考什么**：行不行动得起来。
- **判定标准**每条建议：列出即得分，但出现下列任一硬伤则**该条不得分并记录扣分原因**：
  1. **无对象**：说了"立即撤离"但没说撤谁、撤哪（场景中对象必须落到具体村庄/人群）。
  2. **资源超配**：动用了场景资源清单里没有的资源（如 S001 无直升机却"派直升机巡查"）。
  3. **与情报冲突**：建议与已确认事实矛盾（如道路已断还"通过县道撤离"且未提绕行）。
- **得分公式**：决策层得分 = 有效得分的要点数 ÷ 总要点数。
- **决策"质量附加分"（v0.2 预留）**：试水版暂不加分，仅记录"优先级排序是否合理"的观察项，供错误分析使用。

## 六、打分实现（两种方式）

1. **规则打分（关键词匹配）**：用场景 JSON 中每个要点的 `match` 词表在回答文本中查找，命中 ≥1 词即得分。优点是免费、零波动；缺点是"提到词≠答对"，可能虚高。定位：开发自检用。
2. **LLM 打分（正式）**：把"要点清单 + 智能体回答"交给独立的裁判模型（judge，与被测模型同 API 但角色隔离），要求逐条输出 0/1 和一句理由。定位：报告的正式数字。
   - judge 提示词模板：

```
你是灾害应急决策评测的裁判。下面是场景的评分要点（分层列出）和一个智能体的回答。
请逐条判断要点是否在回答中被满足，只输出 JSON 数组：
[{"层":"事实层","序号":1,"得分":0或1,"理由":"一句话"}]
判定规则：
- 事实层：回答中提到该要素（同义可）得1；
- 推理层：回答完整呈现"起点-机制-终点"链条得1，缺要素得0；
- 决策层：建议被明确给出得1；若建议出现"无对象/资源超配/与情报冲突"任一硬伤得0；
- 只判断"要点是否被满足"，不评判回答的其他内容。
```

3. **一致性保障**：全量结果出来后，随机抽 20% 场景由第二模型复打，报告两者一致率（Cohen's kappa）；再由我（标注者）人工复核全部 0/1 判定中的分歧项。

## 七、指标定义（会画进论文的图）

- **三层得分**：事实层/推理层/决策层各自的"命中率"（§二~四公式）。
- **综合得分**：三层等权平均，仅作总览排序用，论文正文以分层结果为主。
- **决策代价附加项**：记录每条推演的 API 调用次数与耗时，作为"协作成本"的对比维度。
