## 二、三个候选选题（从综述的 7 个 Gap 里筛出来的）

### 选题 A：中文灾害多 Agent 决策基准 + 知识增强收益实证 ★推荐

- **问题**：灾害多 Agent 决策没有基准（这是综述里最硬的一个空白：评测都在办公/代码/旅行域；灾害域只有"培训效果"评测 Sim911，没有"决策质量"评测）。
- **做什么**：
  1. 手工设计 40-60 个**中文灾害决策场景**（地震/洪涝/山火/化工/台风，含 10+ 个"链式次生灾害"场景，如：地震→水库裂缝→下游溃坝风险→要不要撤离）；
  2. 每个场景三层标注：**事实层**（信息有没有提全）/ **推理层**（因果链对不对）/ **决策层**（行动建议合不合理）——三层标注本身是基准的贡献；
  3. 用 3 种框架（单 Agent-ReAct / AutoGen 多 Agent / 带知识库的多 Agent）+ 2 种模型（DeepSeek/GLM）跑全量评测，产出"什么配置在什么场景赢"的消融矩阵。
- **创新点**：第一个中文灾害多 Agent 决策基准；"三层标注"体系；消融发现（预期会发现：多 Agent 提升推理层但拖累事实层；知识增强主要救决策层——这类反直觉发现就是论文的贡献）。
- **工作量**：场景设计 2-3 周、API 实验 1-2 周、分析写作 2-3 周。全部可在你现有电脑完成，API 花销约几十到一百元。
- **投稿**：IJDRR / IJIS（灾害与信息领域期刊，审稿快）/ EMNLP Findings（会议，11 月截稿季）/ ACL 类会议。**首投建议 IJDRR**——你复现过它的论文（E-KELL），领域匹配度最高，期刊审稿比顶会友好。
- **风险**：低。"基准+消融"没有翻车点；唯一风险是评审觉得"只是调 API"——对策是场景设计和三层标注做扎实，并加一个轻量机制（见选题 C 的融合打法）。

### 选题 B：灾害知识闭环（CogMG 灾害化）

- **问题**：应急知识库不敢自动更新，Agent 推演遇到知识缺口就卡住。
- **做什么**：给多 Agent 加"缺口捕获→候选三元组生成→规则审核→写回"闭环，评测 N 轮推演后知识库自增长对决策质量的提升曲线。
- **优点**：机制完整、故事漂亮（14 CogMG 的模板直接搬）。
- **缺点**：要求有一个"会成长的知识库"+跨轮次实验设计，链条长、变量多，**失败点比 A 多两个**；且"写回"环节安全审核的评判标准难定，容易被审稿人挑。
- **风险**：中高。不建议第一稿。

### 选题 C：验证感知的灾害 Agent（VERIMAP 灾害化）

- **问题**：灾害决策的约束天然可形式化（资源守恒、空间一致、时序合法），但没人把它做成 Agent 的"验收关卡"。
- **做什么**：给决策链每个子任务配可执行校验函数（比如：调配的资源总量 ≤ 可用资源；撤离路线经过的桥 < 已损毁列表），校验不过自动重规划。
- **优点**：机制新（52 号思路+灾害领域首次）、实现不算重、和危机 sight 系统无缝衔接（你的系统已经有四 Agent+知识库，加一层"校验官"就行）。
- **缺点**：纯机制工作容易变成"又一个调 prompt 的"，需要场景实验撑住故事。
- **风险**：中。

### 我的建议：**A 为主干 + C 做机制亮点的合体**

基准是"必须有人做的空白"，机制是"证明你不只是拼积木"。两个都做太重，折中方案：
- 主干是 A（基准+三层标注+消融）；
- 机制部分做一个**mini 版验证感知**：给决策层加"资源/空间一致性校验"作为基准里的一个"组件维度"（而不是独立大机制），消融出"带校验 vs 不带校验"一行差值。
- 这样一篇论文有两个贡献（基准 + 一个可验证的机制增益），回头想转 B 或 C 的深水区都有踩点。

## 三、推荐选题的完整拆解（选题 A+C 合体）

### 论文故事线（一句话）

> 灾害应急里大家都在谈论用多 Agent 辅助决策，但既没有评测它的基准，也不知道知识增强到底在哪里起作用——我们造了第一个中文灾害多 Agent 决策基准 CrisisBench，并用它发现：多 Agent 帮推理、害事实，知识增强救决策，而一层廉价的约束校验能以 1% 的成本换回一致性。

### 三大贡献

1. **CrisisBench 数据集**：N 个中文灾害决策场景 ×三层标注（事实/推理/决策）× 评分细则；
2. **系统评测**：单 Agent-ReAct vs 多 Agent（情报-研判-决策-审核）vs +知识库增强 vs +约束校验，跨 2 个模型、多个消融；
3. **发现**：反直觉结论若干条（下面实验设计会写预期）。

### 数据设计（你的核心武器）

- 场景 =（灾种，时间点，已有情报片段 5-8 条，可用资源清单，正确决策要点）
- 三类难度：单灾种 / 链式次生灾害 / 信息矛盾（故意放两条冲突情报，看 Agent 会不会置信度判断）
- 每个场景的标注（自己手工做，这是"自己做的内容"）：
  - 事实层要点：如"应提到上游水库有裂缝"
  - 推理层要点：如"应推出裂缝→溃坝风险→威胁下游三角带人口"
  - 决策层要点：如"应建议 3 村撤离+坝体应急放水+监测加密"
- 评判：LLM 打分 + 人工复核抽检（打分一致性报告本身就是实验细节）

### 实验矩阵（最小可行）

| 轴 | 取值 |
|----|------|
| Agent 配置 | 单Agent-ReAct / 4-Agent 协作 / 4-Agent+知识库 / 4-Agent+知识库+约束校验 |
| 模型 | DeepSeek-chat / GLM-4-flash（两条 API，都能白嫖额度） |
| 难度 | 单灾种 / 链式 / 信息矛盾 |

三层得分 ×4 配置 ×3 难度 ×2 模型 = 全量跑一遍约 60 场景 ×4 配置 ≈ 240 次推演 ×2 模型 = 480 次 API 调用级别，**成本可控**。

### 预期发现（写进假设，实验验证）

1. 多 Agent 在"推理层"显著优于单 Agent（互相校验），但在"事实层"会**差**（信息在传递中丢失/被改）——这呼应你 09 笔记里"幻觉级联"的担忧，值得深挖；
2. 知识增强的增益集中在"决策层"（知道标准应对要点才能给出合格行动建议），对事实层几乎无效；
3. 链式次生灾害是所有配置的分水岭——现有框架全都塌，验证你的"态势演化"gap；
4. 约束校验能揪出"资源超配/路线穿越损毁区"一类的低级错误，以极低成本换来一致性提升。

## 四、0→1 的六个阶段

### 阶段 0：定题与最小验证（1 周）
- 和我一起把上文拆解变成正式的一页纸 proposal（问题/贡献/方法/实验/计划）
- 先设计 **5 个场景**（各难度 1-2 个）+ 三层标注，跑通 1 个配置
- 里程碑：一个能跑的实验脚本 + 5 场景数据文件 + 你觉得难度把握对了

### 阶段 1：数据设计（2-3 周）
- 把场景扩到 40+（含 10 个链式、8 个信息矛盾）
- 三层标注 + 评分细则文档（rubric 化）
- 让 3 个不同"评审小模型"互相打分做一致性检测（kappa），人工复核
- 里程碑：CrisisBench v1.0 数据文件 + 标注手册

### 阶段 2：实验（2 周）
- 4 配置 × 2 模型全量跑（脚本化、可复现、记录 token/成本）
- 每次推演存原始输出（审稿人要看的能拿出来）
- 里程碑：全量结果表 + 原始输出归档

### 阶段 3：分析（1-2 周）
- 三层得分统计 + 显著性检验（这个我会教你，很简单）
- 错误分析：逐条看失败样例归类（"事实丢失"“因果断裂"“资源超配”……这套分类本身是论文的表 5）
- 反直觉发现提炼
- 里程碑：结果章节的所有图表

### 阶段 4：写作（2-3 周）
- 结构完全照抄你读熟的模板（Intro 写法参考 63 Sim911 和 09 危机的开篇：场景→痛点→为什么难→我们干了啥）
- 我陪你一段一段写，每段给你讲"这段在回答审稿人什么问题"
- 里程碑：完整初稿

### 阶段 5：打磨与投稿（2 周）
- 自己冷读 3 遍（隔夜读、打印读、出声读）
- 投 IJDRR（复现过它的论文，知己知彼）/ 或先投 EMNLP Findings 抓会议节奏
- 里程碑：投出去。**投出去就算赢**，拒稿在计划内。

### 时间上的诚实提醒
按每天 2-3 小时投入，全部周期大致是一学期节奏。如果阶段 0 的 MVP 跑不通（比如打分一致性太差），回到选题重选，损失只有 1 周——这就是阶段 0 存在的意义。

### B. 章节修改清单（对齐 EMNLP/ARR 惯例）

1. 全文英文改写，ARR 模板（双栏，8 页正文限）；
2. 题目突出三元素（基准 + 裁判不可靠 + 确定性校验），如 "CrisisBench: Benchmarking Multi-Agent LLMs for Disaster Situation Reasoning and Decision Support"；
3. 结构调整：Introduction → Related Work（精简）→ Task & CrisisBench（设计原则、两层校准记录）→ Evaluation Protocol（三裁判多数票）→ The Verifier（C 组件）→ Experiments（setup + RQ1~RQ4）→ Analysis（错误类型学）→ **Limitations（ARR 强制）** → Ethics Statement → References；
4. 实验结果按 4 个 RQ 组织：RQ1 多 Agent 是否更好；RQ2 增益来源（角色消融）；RQ3 LLM 裁判可靠吗；RQ4 确定性校验能否替代/纠正 LLM 核对；
5. 图表 4~6 张：三层得分雷达图、分场景热图、裁判一致性混淆矩阵、multi vs multi+verify 硬要点条形图、成本散点；
6. Limitations 如实写：场景为人工虚构且初稿经 AI 辅助（投稿前本人逐条审改、声明留数据卡）、仅两家 API 模型、无现场部署验证；
7. 数据与代码发布：评审期匿名版本上传 Zenodo（数据 CC-BY-4.0）+ README + HuggingFace 数据卡；arXiv 预印本确认 ARR 政策后投；
8. 引用补强并逐条核实：LLM-as-a-judge（Zheng et al. 等）、基准代表作（HELM / BIG-bench / AgentBench）、灾害 LLM 应用、多 Agent 框架（AutoGen 等）。
