## 一、这个方向到底在做什么

一句话：**灾害发生后，海量异质信息涌入（推文、遥感影像、公文、传感器），需要多个智能体各司其职、互相协作，把信息变成"现在什么情况、下一步会怎么样、该怎么办"的研判结论，供指挥人员拍板参考。**

拆开是四个关键词：

| 关键词 | 含义 | 对应论文群 |
|--------|------|-----------|
| 知识增强 | 不让大模型"裸猜"，先给它查知识（KG/RAG/规则库）再说话 | 线上 B 线 |
| 多 Agent | 多个角色分工协作，互相质疑、校验、汇总 | 线上 C 线 |
| 灾害态势推理 | 从碎片信息推出全局态势，含时间演化（会发生次生灾害吗） | 线上 A + D 线 |
| 辅助决策 | 产出给"人"的建议而非自动执行；可追溯、低幻觉、能解释 | 线上 D 线 |

按数据流，该方向的完整链条是：

**信息入口（识别/清洗）→ 知识增强推理（关联/补全/演化）→ 多 Agent 协作研判 → 决策建议 + 复盘反哺**

下面按这条链逐段讲"进展到哪一步、代表工作怎么实现的"。

## 二、链段 A：灾害信息入口——从碎片信息到结构化要素

**要解决的问题**：灾害期间信息又杂又乱（一天百万条推文），先得把"有用的"挑出来、贴上类别标签、落到地图上。

**进展到哪一步了**：

1. **早期**：监督模型要标注、要训练，换个灾害就不灵（09 号论文交代的动机）。
2. **现在**：用 LLM 零样本直接分类，省了训练，但**仍打不过监督模型**——09 号论文（WWW'25）拿 6 个大模型考 7.7 万条推文，最好的 GPT-4o 宏 F1 0.762，低于监督 RoBERTa 的 0.78。而且三类"软肋"被系统测出来：**洪水数据最差、求助/急需类最容易错、错别字显著降分**。我们复现里补的实验还证明了：这条软肋的因果在错别字本身，不是相关性。
3. **再往前**：60 号 DisasterTD（TGRS）解决"地名歧义"——MLLM 从推文抽地名生成候选坐标，再用 DINOv2 把现场影像/遥感图/街景做**跨视角余弦匹配**，"语义出候选、视觉做裁决"，Harvey 飓风 1km 内定位 71.6%。
4. **最前沿**：61 号 RescueADI（TGRS）把孤立任务（检测/分割/VQA）合并成"自适应灾害解读"：Agent 自己规划"先测建筑损伤+道路阻塞，再判可达性"，按需调用检测/分割工具。比传统 VQA 高 9%。23 号 Taming the Untamed 则在罕见领域用**多 Agent 自搜索图**补多模态知识。

**这一段的成熟度判断**：LLM 分类"能用但不放心"，地名落图和综合解读刚起步，中文场景（微博/郑州暴雨这类）几乎空白——**这是离我们最近的缺口**。

## 三、链段 B：知识增强推理——KG 与大模型的融合

**要解决的问题**：大模型会编（幻觉）、不知道最新事实、推理没解释。知识图谱（KG）正好补这些。

**演进路线（这段发展最快，读下来的感受是"三年走了别的领域十年的路"）**：

### 第 1 代：把知识"喂"给模型
- 06 RAG（NeurIPS'20）奠基：检索-生成范式。
- 10 Roadmap（TKDE）画了总蓝图：KG 增强 LLM / LLM 增强 KG / 双向协同三大框架。灾害方向第一梯队的工作（05 E-KELL）就是"KG 增强 LLM"落地的例子：把 XAI-Emergency 图文+规则转成知识图谱给模型查，问答 F1 从 59.31% 涨到 65.63%。**我们复现过，它对冷门领域题（Q10 火灾行为）直接拒答——单给 KG 还不够。**

### 第 2 代：从"查句子"到"查关系"（GraphRAG）
- 11 GraphRAG 综述把新范式定型：**建图索引→图引导检索（实体/三元组/子图/社区）→生成**。20 RAG vs GraphRAG 给了定位：RAG 强在单跳细节，GraphRAG 强在多跳推理，融合多跳 QA 最高 +6.4%，但建图成本高。
- 27 GRAG 用 top-N ego-graph+软剪枝降低子图爆增问题；30 KG2RAG 沿 KG 做 m 跳 BFS 扩张再最大生成树滤噪，HotpotQA 全维基 F1 至少 +8%。
- 16 GFM-RAG 更激进：训练一个 8M 参数的**图基座检索器**，60 个 KG 上预训练后零微调跨域迁移，符合缩放律——"图检索器"本身成为可复用组件。

### 第 3 代：闭环与自我修正
- 24 MetaKG-RAG：KG-RAG 是"开环"的，检索漂了没人管。改造成 **感知→评估→调整**闭环（查路径覆盖、评估证据缺失、从最优枢轴点定向重搜），5 数据集最高 +10.35%。
- 14 CogMG：另一个闭环，但对象是**知识本身**——问答时发现 KG 缺三元组，就分解需求→参数知识补全→外部文档验证→写回 KG。更新后准确率 40%→86%。

### 第 4 代：时序与演化（和灾害最相关的一条）
灾害态势的命门是"事情在变"：震后 2 小时 vs 48 小时完全两码事。
- 12 STCQA：首个时空 KGQA 框架，联合时空嵌入+按"within 3 miles"这类约束动态过滤，Hits@10 84.29，超 GPT-4o（13.73）几个量级。
- 21 SSTKG（已有笔记）：时空图谱太复杂，砍到"简单三部曲"反而赢——交互表示+轨迹表示+时空聚合。
- 15 DECRL：对"三个以上实体同时相关"的高阶关系做演化聚类（模糊 c-means+簇间对齐+时间平滑），7 数据集全面涨 9-15%。
- 22 TCompoundE：复合几何操作（平移+缩放）建模时序，ICEWS14 MRR 0.644。
- 19 LLM-DA：不用微调，LLM 引导随机游走挖**时序规则**并动态刷新，TiRGN MRR 0.441→0.471。这条有亮点：规则是人类能读的解释。

### 这条线上的"基础设施"进展
- 自动建图：13 AutoSchemaKG 摆脱专家预定义 schema，从 5000 万文档建 9 亿节点的 ATLAS；14 CogMG 让 KG 随用随长。
- 知识编辑：29 GLAME 解决"编辑一个知识点引发关联知识不一致"——用 KG 邻居子图把衍生变化一次性焊进模型（Portability +11%）。
- 可扩展推理：18 KnowFormer 用 Transformer 注意力做 KG 推理，绕开消息传递的路径缺失/过压缩问题。

**这一段的成熟度判断**：技术上 GraphRAG/闭环/时序都已现成，**"拼"的难度不大，真正的空白在灾害领域的定制**：灾害 KG 怎么建（事件链/因果链怎么表示）、时空约束怎么和"决策"挂钩、知识更新怎么在应急场景落地（没人敢让机器自动改应急知识库）。

## 四、链段 C：多 Agent 协作——从"人工组队"到"自动编排"

**演进路线**：

### 第 1 代：对话即协作（2023）
- 07 ReAct 是单 Agent 底座：**想一步做一步**（Thought-Action-Observation），调 Wiki 搜索，HotpotQA EM 27.4→35.1。我们复现踩过它最出名的坑：模型会**假装调用工具**——动作格式一松就输出"Search[...] 已找到"，必须严格解析+校验返回。
- 08 AutoGen（COLM'24）推广到多智能体：UserProxy 执行、Assistant 出主意，公开对话是唯一信息通道，支持人中途介入。41 综述（IJCAI'24）整理了四大维度：环境接口、角色画像、通信、能力习得。

### 第 2 代：编排自动化 + 成本意识（2024-2025）
- 42 MetaAgent：不靠人定义角色，设计者 LLM 自动生成"最少必要的 Agent"+ 有限状态机控制流，状态可合并回溯，强于手工设计。
- 48 稀疏辩论：辩论不一定全连接——正则图邻居连接+异步发言，MATH 还涨 2% 且省 41.5% 成本。**强模型放中心度高的节点**。
- 17 KABB：用"知识距离"（概念重叠+依赖路径+历史表现衰减）做贝叶斯 Bandits，动态只选 2 个专家就超 6 个专家的 MoA 9.8%。
- 44 SYMPHONY：异构模型池+MCTS 搜索，熵调制置信度压制不可靠 rollout，WebShop 跑分超人类专家。
- 40 APC：把历史成功计划的"骨架"缓存复用，平均省 50.31% 成本——测试时记忆。

### 第 3 代：闭环化——带着"验证"和"记忆"干活（2025-）
- 52 VERIMAP：Planner 拆 DAG，**每个子任务配一个可执行验证函数**（Python 检查格式/类型/正确性），验收不过才交接，不过就重试/重规划。五数据集全面超 ReAct/SOTA。
- 49 LEGOMem：把历史成功轨迹蒸馏成**分层程序性记忆**（编排器拿全局、任务 Agent 拿子任务记忆），纯小模型团队带记忆后超过不带记忆的混合团队。
- 50 PMC：多约束任务（预算/时间）由 Manager 拆"有向子任务图"，区分**局部约束/全局约束**，Supervisor 在执行前改写实例化参数。TravelPlanner 42.68%（GPT-4 裸跑只有 2.92%）。

**这一段的成熟度判断**：协作范式已经从"提示词工程"变成"系统工程"——状态机、验证函数、记忆库、成本调度都齐了。**但灾害场景一个都没有**：现有评测全在数学/代码/旅行/办公域。灾害决策的独特约束（致命后果、时间压力、信息残缺、链式次生灾害）没人系统建模过。这就是 C 段的空白。

## 五、链段 D：灾害领域落地——已有的四个脚印

| 工作 | 干了什么（实现方式） | 局限 |
|------|--------------------|------|
| 05 E-KELL（IJDRR'23） | 灾害事件+KG+GPT-3.5 的问答系统，KG 来自美国 2013-2015 历史事件三元组 | 静态问答；冷门题拒答；不是多 Agent |
| 63 Sim911（AAAI'25） | LLM 扮演 911 调度员+事件模拟器训练人员，知识构建+受控生成+循环验证三件套，发现低收入社区训练表现差 44.44% vs 77.98% | 面向培训模拟，不做态势推理决策 |
| 62 LogiDebrief（IJCAI'25） | 复盘自动化：STL 信号时序逻辑把演练需求转成可验证公式，LLM 判定通过与否，覆盖率 73.96%→85.05% | 事后复盘，不指导事中决策；依赖 STL 表达力 |
| 60/61 DisasterTD/RescueADI（TGRS） | 地名落图、遥感综合解读（见链段 A） | 感知层，没走到决策层 |

**读完全部的直接感受**：灾害领域这四个脚印是分散的——感知、问答、培训、复盘各做各的，**中间"多 Agent 协作研判决策"这一段是空的**。而通用多 Agent 技术（链段 C）已经足够成熟可以搬过来，知识增强技术（链段 B）也有现成组件。中间少的是一个"翻译者"：把灾害领域的约束（资源、时间窗、次生灾害链、致灾因子）建模进这些通用框架，并且建立一套能评测这个过程的基准（线的另一头：40/47 是别人的评测、09 是入口层评测，唯独"多 Agent 灾害决策"没有）。

## 六、整体进展判断（大白话版）

1. **入口层**：LLM 分类"能用"，但代价是比监督模型差一截；多模态+跨视角验证是新的增长点；中文灾害几乎空白。
2. **知识层**：论文最多、卷得最凶。GraphRAG→闭环→时序演化三步走完，教科书式成熟。做"新图表"卷不过，做"灾害领域定制+验证"有空间。
3. **协作层**：机制(FSM/验证/记忆/成本调度)全部就绪，评测基准都在非灾害域。把成熟机制搬到灾害+补上灾害约束，是技术门槛最低、叙事最完整的切入点。
4. **落地层**：四个脚印分散且停止在"问答/培训/复盘"，**没有人把"多 Agent"与"知识增强"合体完成一次灾害全链条决策**。

**结论一句话**：这个方向不新潮，但"灾害领域 × 多 Agent × 知识增强"的交集是真实的空白，而且所有零件都已成熟——适合"用现成零件拼领域首个验证"的起步型论文。

## 八、给起点研究生的建议（重要）

诚实地说：这条线上的**强方向（1、2、3）都需要"数据/场景设计师"的角色**——手工设计灾害场景、标注、跑 API、写评估脚本。这恰好是：
- 不需要训练大模型（用 DeepSeek/GLM API 即可，成本可控）；
- 你已经在复现里练过（E-KELL 评测、危机推文三版实验都是这个模式）；
- 贡献可检验（基准公开可复现，创新点消融干净）。

代价是"工程量大、创新点上需要克制"。强创新点（4、5）更吃机制设计但风险更高。二者有个黄金组合，见路线图文档。
