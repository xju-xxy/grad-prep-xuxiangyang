# 07 ReAct 论文笔记

**论文**：ReAct: Synergizing Reasoning and Acting in Language Models
（Shunyu Yao 等，Princeton + Google Research，ICLR 2023，arXiv:2210.03629）
**读的时间**：2026年10月

---

## 一句话总结

以前的 LLM 要么只会"想"（CoT），要么只会"做"（Act），这篇把两者拧成一根绳：
让模型在"想一步 → 做一步 → 看结果 → 再想下一步"的循环里干活，推理指导行动，
行动的结果反过来纠正推理。

## 论文具体干了啥

作者发现一个很自然的割裂：研究推理的人搞 CoT（一步步写思考过程），研究行动的人
搞 tool use（调 API、操作环境），两边各玩各的。CoT 的问题是纯靠脑子想，不接触外部
世界，容易一本正经地编造事实——比如问"这个饭店几点关门"，它凭记忆瞎答；
Act-only 的问题是不会分解目标，闷头乱动。ReAct 的想法就是把 Thought / Action /
Observation 三种东西交错拼在一起：想一步，做一个动作，把动作的观察结果塞回
上下文，再想下一步。

动作空间被扩充成 A ∪ L，L 是语言空间——意思是"说一句话"也可以是一种动作。
Thought 被定义成"不影响外部环境的动作"，只更新模型自己的上下文。具体到实验里，
配的是最简单的 Wikipedia 工具包：search（查相关页面）/ lookup（在页子里找关键词）/
finish（给答案），模型冻结（PaLM-540B）+ 少量人类示范轨迹做 in-context，没动权重。

还有个细节我印象挺深：thought 该密该疏由模型自己看着办。知识推理类任务
（HotpotQA、Fever）把思考写密一点有用，决策类任务（ALFWorld 文字游戏、
WebShop 网上购物）想太多反而增加出错点，稀疏一点好。

## 实验数字（挑记得住的）

- HotpotQA：ReAct 接过 CoT-SC 后 EM 到 35.1，超过单纯 CoT-SC 的 33.4
- Fever：64.6%
- ALFWorld：ReAct 71% vs Act-only 45% vs 学过的 BUTLER 37%
- WebShop：40.0 vs 强化学习基线 28.7——就靠 1 到 2 个示例，压过用十几万条
  数据训出来的方法，这是最唬人的一个对比。但人类专家是 59.6%，差距还在。

## 和我的复现经历

这篇是我最早动手复现的一篇（research/reproduction/react-demo）。当时踩的最大的坑是：
模型会"假装"调用工具——输出长得像工具结果，其实工具根本没执行，或者直接编一个
答案糊弄我。最后是靠严格解析动作格式 + 校验返回结果兜底：解析不出合法动作就
重试，没有真实的 observation 就不让链继续往下走。折腾完回头看论文，其实作者
自己也在局限里写了"连接外部环境有安全风险、容易出错"，算是论文里一句轻描淡写、
工程里一个血泪教训。

## 我没完全想通的点

1. thought 的稀疏/密集完全交给模型，结果就是不稳定。同一道题跑两次，一次想三步，
   一次想十步。能不能用任务类型去约束这个自由度？
2. 作者说和强化学习结合留给 future work。如果我给它接个 Alpaca 类小模型微调，
   few-shot 的稳定性会更好还是更差？没想清楚。
3. 多 Agent 场景下，每个 Agent 内部都跑自己的 ReAct 循环，token 消耗会非常感人。
   论文只讨论单 Agent，没有给成本账。

## 和我方向的挂点

"知识增强的多 Agent 灾害态势推理"里，每个 Agent 干活的基本姿势就是 ReAct：
情报 Agent 查知识库、研判 Agent 看证据、决策 Agent 出方案，每一步都要 grounding
（落在真实数据上）。ReAct 给我们的是"单兵动作规范"；知识增强解决的是 observation
从哪来、可信不可信；多 Agent 解决的是多个这样的循环怎么协作。三块正好拼起来。
另外 thought 链天然可审计——灾害决策场景里"你为什么这么判"必须答得上来，
这一点 ReAct 比黑盒生成更有底。
