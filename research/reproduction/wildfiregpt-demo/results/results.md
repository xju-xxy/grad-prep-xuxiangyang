# WildfireGPT 复现结果

> 对应复现：wildfiregpt-demo（模型：智谱 glm-4-flash，嵌入：embedding-3，2026年10月）
> 这一页的三阶段输出都是 `agent.py --auto --log results/auto_log.md` 真跑出来的，原文在 auto_log.md。
> 跑的就是论文里"景观管理员想安排控制烧"那个案例的本地版。

## 跑的这个案例

用户开场：某林场营林技术员，林场里是栎类/橡树次生林，林下枯落物堆了很多年，
想赶在春季返青前做一次计划烧，既维护橡树更新，又怕火控不住影响山下两公里的村子，
问怎么平衡。

## 阶段一：用户画像（问诊）

Agent 自己连着问了 5 个问题（经验、担心什么、哪块地方、时间线、想了解什么），
每个问题我这边按关键词回一句预设答案，最后它自己汇总成结构化画像：

```json
{
  "role": "林场营林技术员",
  "concern": "计划烧失控，烟和飞火影响山下居民区",
  "location": "华北某山区林场，南侧约2公里有村庄",
  "timeline": "春季返青前，约一个月准备时间",
  "focus": "计划烧窗口期选择、气象条件门槛、居民区一侧防护措施"
}
```

这一段跑得出乎意料地顺，模型没有一次把"我该问什么"问成"我该答什么"。
只有一个小毛病：第 5 个问题它把"维护橡树更新"和"防护措施"混着问了，
画像里的 focus 因此少了"生态目标"这一条，这个缺失在后面阶段被放大了（见下）。

## 阶段二：规划

它给的计划长这样（摘关键部分）：

```
参考知识：火险指标 / 气象地形 / 植被燃料 / 控制烧 / 社区防护 / 应急物资
分析步骤：
  1. 收集火险指标、气象数据、地形图、植被分布等资料
  2. 分析气象条件，确定计划烧窗口期和气象门槛
  3. 评估植被燃料状况，确定点火顺序和隔离带设置
  4. 制定居民区一侧的防护措施和应急响应计划
  5. 综合评估，优化计划烧方案
建议内容：窗口期建议 / 气象门槛 / 居民区防护 / 应急物资清单
```

计划本身像模像样，但它只是"打算做什么"的清单，没有具体结论——这点符合我提示词里
"结论留到分析阶段"的要求。自动模式直接确认执行。

## 阶段三：分析师（检索 + 带引用）

它自己拆成 3 个分析步骤，每个步骤配一句检索查询词，程序拿查询词去知识库做向量检索，
命中条目连同原文一起喂回模型，模型再写带 `[条目id]` 引用的分析。实际命中和输出：

**第 1 步 分析火险风险和确定计划烧窗口期**，查询 `华北山区火险等级评估方法`
命中 `[MON-03] 火险等级发布与禁火令、[LINE-05] 居民区周边可燃物清理、[FWI-07] FWI 等级与防控措施对应、[FUEL-04] 灌草坡地的火灾风险`。
输出里能看出它在拿着 FWI-07 的等级对照表说"很高和极高档会触发停止计划烧"。这一段引用是实的。

**第 2 步 确定气象条件门槛和选择窗口期**，查询 `春季华北地区气象条件对计划烧的影响`
命中 `[BURN-02] 计划烧的窗口期怎么选、[BURN-06] 人员与安全线准备、[BURN-03] 气象条件门槛、[BURN-07] 审批与报备`。
这一步检索质量最好，四条全是控制烧直接相关的，输出也把窗口期、气象门槛、审批、安全线串成了完整一段。

**第 3 步 评估植被燃料状况和制定点火顺序**，查询 `华北山区植被燃料干燥程度和载量评估`
命中 `[FUEL-04] 灌草坡地火灾风险、[FUEL-05] 可燃物载量与连续性、[ECO-03] 火烧迹地植被恢复与再燃、[FUEL-06] 林下枯落物堆积的隐患`。

**综合建议**给了 7 条"可以怎么做" + 注意事项 + "什么情况下不要做"，
里面明确写了"避免在极高 FWI 等级或极高 ISI 值时进行计划烧"。

## 真跑出来的几个问题（不是设想，是这次跑完发现的）

**1. 用户的生态目标被漏掉了。** 这个案例是"平衡生态（橡树更新）和居民区风险"两头，
但画像阶段 focus 就没记下生态这条，规划和分析阶段也就一路只谈安全和防护，
知识库里明明有 `[BURN-04] 计划烧的生态作用`，三个阶段谁也没提。
最后给的建议是一份合格的"安全指南"，但不是用户问的"怎么平衡"。
我猜是因为问诊把"维护橡树更新"当成了背景了解掉，没有当成一个要写进画像的目标。

**2. 检索是纯语义相似度，查询词写歪就跟着歪。** 第 1 步的查询
"华北山区火险等级评估方法"命中了 `LINE-05 居民区周边可燃物清理`，跟"火险等级"其实不太搭，
只是因为都带"防火/风险"味道被向量拉近了。语料只有 50 条还不明显，
量大了这种"看着相关其实跑题"的条目会拖累整段分析。

**3. 综合建议那一段没有标注引用。** 前面三步分析都老老实实带 `[条目id]`，
到最后的综合，模型把依据省了，只在正文里复述结论。我提示词里要求了标引用，
它没完全照办。所以最终建议里那些话，要回溯到具体知识条目得看回前面三步。

**4. 自动问答第一版答非所问。** 一开始我按"第几个问题"硬塞答案，
但模型每次提问顺序不固定，结果问时间线它答了地点，画像直接错乱。
改成按问题里的关键词路由答案（问"经验"回背景、问"时间"回时间线）之后才对齐。
这也说明：让 Agent 自由提问，配一套固定的假答案很容易错位。

## 和论文比

- 论文的文献库是 CIACC 的真实论文，我换成自己整理的 50 条中文野火科普条目，
  量级小很多，但"检索→带引用生成"的链路是一样的。
- 论文用 all-MiniLM-L6-v2 + Faiss 做向量检索，我用智谱 embedding-3 + numpy 手写余弦相似度
  （相当于一次全库 kNN），没装 Faiss。降级原因在 README 里写了。
- 论文有 4 个案例和四位维度的人工评分（正确性 97.73% / 相关性 98.20% / 蕴含性 93.75% / 可及性 95.49%），
  我只跑了 1 个案例，也没有领域专家打分，只能自己看输出合不合理。

## 结论

三阶段是真的跑通了：问诊收集画像 → 生成计划并确认 → 检索知识库出带引用的分析，
每一步的程序输出（提问、检索命中了哪几条、模型生成的原文）都在 auto_log.md 里对得上，
没有模型自己假装检索的痕迹。

但"跑通"和"好用"是两回事。上面第 1 条那个漏掉生态目标的毛病，
让我意识到这套流程的瓶颈可能不在检索、不在模型，而在**画像是怎么建的**——
画像少写一条，后面全都歪。
