# LLM 危机推文鲁棒性评测 复现笔记（第 4 篇）

> 复现论文：Evaluating Robustness of LLMs on Crisis-Related Microblogs across
> Events, Information Types, and Linguistic Features（arXiv:2412.10413，WWW'25）
> 用到的模型：智谱 GLM-5.3-Flash（API 调用）
> 时间：2026年10月

## 这项目干了啥

一句话：灾害期间推文满天飞，我拿大模型当"免费分类器"，把它在四类灾害
（飓风/地震/野火/洪水）上的软肋挨个测了一遍。

论文的设定很朴实：灾难发生时一天几百万条推文，里面全是噪音，指挥中心
需要知道"哪条在求助、哪条在报损毁、哪条纯聊天"。传统做法是训练
监督模型，又贵又慢还换个国家就失灵。论文就问了：大模型不训练、
直接凭提示词上场，能干到什么程度？

我照着复现的是一条完整管线：从 HumAID 数据集抽样本 → 按论文原文提示词
让 GLM 分类 → 算宏 F1 出表。核心看点有三块：

1. **zero-shot 和 3-shot 差多少**：论文说给示例基本没用，我拿 GLM 验证了一遍
2. **哪种灾害、哪类信息最难**：论文说洪水最难、"求助/急需"最难分，
   我的小样本上成不成立
3. **错别字到底伤不伤**：论文用回归证明错别字拉低性能，我改成更直接的
   "同一条推文、有错别字 vs 没错别字"对比，掉多少一眼可见

每一步的预测都缓存在 predict_cache.json 里，跑挂了重跑会自动续上。

## 关于数据集，说清楚

HumAID 是卡塔尔计算研究所（QCRI）做的人工标注推文数据集：
2016-2019 年 19 场灾害、77,196 条英文推文，每条标注了一个人道信息类别。
官网（crisisnlp.qcri.org/humaid_dataset.html）把数据分成两份：

- **set1（47,868 条）**：直接给下载链接，一分钟下好
- **set2（29,328 条）**：要填谷歌表单申请，我等不起

所以我只用 set1。set1 里有 11 个事件的完整 train/dev/test 三个分片，
我按"四类灾害各一个事件"挑了 4 个作为评测：
哈维飓风(2017，美)、墨西哥普埃布拉地震(2017)、加拿大野火(2016)、
斯里兰卡洪水(2017)。论文里"洪水最难"的结论，我这里的洪水样本就是
斯里兰卡洪水。

**两个要提前交代的裁剪/妥协：**

1. **规模**：论文在一个事件几百上千条 × 6 个模型 × 5 种 shot 上跑，
   我只有一个 GLM API，为控制成本每事件每类只抽 14 条（共 406 条），
   只测 0-shot 和 3-shot。样本固定随机种子，存在 sample.json，
   谁都能复现我这套样本。
2. **MFP 类缺席**：missing_or_found_people（失踪/寻人）这整个类别
   在我选的 4 个事件的全部 tsv 里一条标注都没有（这不是抽样截掉的，
   是 HumAID 官方这几个事件本来就没标）。另外加拿大野火没有"伤亡"类、
   普埃布拉地震和斯里兰卡洪水没有"撤离安置"类。所以每个事件只有 7~8 个
   类别，宏 F1 按"切片里实际存在的类别"平均——硬把不存在的类塞进去
   算 0 分是耍赖，我在 eval.py 里处理了。

另外有个细节：部分类别在 test 集里凑不满 14 条，我从同一事件的
dev/train 里补了（sample.json 里每条都标了 split 字段，一共 74 条是补的），
这部分也算数据口径差异，坦白在这里。

## 为什么用 GLM 不用 GPT-4o

论文的闭源主力是 GPT-4o。我用智谱 GLM-5.3-Flash 替代，三个理由：
一是国内能稳定调 API，不用折腾 OpenAI 账号；二是便宜，跑一千多次
调用不心疼；三是想看看"中文团队的国产模型"在这类英文危机推文任务上
和 GPT 系差多少——这也是导师可能会问的，我主动测了。
温度、提示词、类别定义都和论文一致，只有模型换了，README 里
所有数字都标注了是 GLM 跑出来的，不和论文数字混着说。

## 怎么跑

```
# 装依赖（.venv 已有的话跳过）
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

# .env 里填智谱 API Key

# 1. 去官网下载 HumAID set1，解压后把 events_set1 文件夹放到 data/ 下
#    https://crisisnlp.qcri.org/data/humaid/HumAID_data_events_set1_47K.tar.gz

# 2. 抽评测样本（生成 data/sample.json 和 data/fewshot_examples.json）
.venv\Scripts\python.exe sample_data.py

# 3. 跑分类（zero + 3-shot + 错别字版，结果缓存 predict_cache.json）
.venv\Scripts\python.exe classify.py --all

# 4. 看评测表
.venv\Scripts\python.exe eval.py
```

## 文件一览

- `sample_data.py` 抽样本：test 优先、dev/train 补足，种子固定
- `classify.py` 分类器：论文原文提示词 + GLM API，多线程 + 超时 + 缓存续跑
- `eval.py` 评测：宏 F1 总体/分事件/分灾害类型/分信息类别 + 错别字对比
- `data/sample.json` 评测样本（406 条，可直接看）
- `data/fewshot_examples.json` 3-shot 用的示例（每类 3 条）
- `predict_cache.json` 所有预测的缓存（模型每次回答了什么都能查）

## 测试记录

跑法：`classify.py --all`（0-shot + 3-shot + 错别字对照），温度 0，N=406 条。
下表所有宏 F1 都是"切片里实际存在的类别"平均，不是硬凑全部 9 类。

### 总体（GLM vs 论文）

| 我的设置 | 宏F1 | 准确率 |
|---|---|---|
| zero-shot | 0.706 | 0.709 |
| 3-shot | 0.736 | 0.724 |
| zero + 重度错别字 | 0.712 | 0.714 |

论文 0-shot 宏 F1 对照：GPT-4o 0.762、GPT-4 0.750、GPT-3.5 0.661、
Mistral-7B 0.628、Llama-2-13B 0.562、Llama-3-8B 0.534，
有监督的 RoBERTa 基线 0.780。

我的 GLM 零样本 0.706，正好夹在 GPT-3.5 和 GPT-4o 中间。但口径不一样
（我 406 条按 8 类口径算，论文 15,160 条按 9 类算），所以只能说
"档次大致可比"，两个数不能直接相减下结论。

### 分事件（三个跑法全列）

| 事件 | 灾害类型 | N | zero | 3-shot | 错别字 |
|---|---|---|---|---|---|
| 哈维飓风 2017 | hurricane | 112 | 0.635 | 0.681 | 0.622 |
| 墨西哥普埃布拉地震 2017 | earthquake | 98 | 0.719 | 0.739 | 0.698 |
| 加拿大野火 2016 | wildfire | 98 | 0.640 | 0.728 | 0.637 |
| 斯里兰卡洪水 2017 | flood | 98 | 0.724 | 0.650 | 0.693 |

### 分信息类别（按 zero 从低到高排，越低越难）

| 类别 | zero | 3-shot | 论文 GPT-4o 参考 |
|---|---|---|---|
| 撤离安置 DPE | 0.571 | 0.723 | 0.88 |
| 求助/急需 RUN | 0.595 | 0.674 | 0.70 |
| 非人道信息 NH | 0.598 | 0.577 | 0.91 |
| 预警建议 CA | 0.667 | 0.660 | 0.81 |
| 救援募捐 RVDE | 0.675 | 0.722 | 0.91 |
| 设施损毁 IUD | 0.816 | 0.747 | 0.84 |
| 慰问支持 SS | 0.849 | 0.854 | 0.91 |
| 伤亡 IDP | 0.874 | 0.930 | 0.94 |
| 失踪寻人 MFP | 4 个事件全无标注，缺席 | — | 0.82 |

混淆最严重的一对：21 条"求助/急需"被模型当成了"救援募捐"，
然后是 15 条"预警建议"被当成"非人道信息"。

### 论文的三个招牌结论，我复现得怎么样

1. **"求助/急需最难分"——复现了。** RUN 零样本只有 0.595（我这边最难的
   是撤离安置 0.571，RUN 第二难），而且最大混淆对就是 RUN → 救援募捐，
   和论文说的一致。
2. **"洪水最难"——没完全复现。** 零样本时洪水 0.724 反而四个事件最高；
   但 3-shot 里洪水是唯一不升反降的（0.650），侧面说明它确实难。
   我猜论文难在 19 个事件的洪水大平均，我这里只有斯里兰卡一个洪水事件，
   样本差异解释得通。
3. **"错别字显著拉低性能"——没复现，反而找出了论文论证的空子。**
   我给样本 50% 的单词加了重度错别字（对调/删字母/重复字母），
   四个事件 F1 只掉 0.01~0.03，总体基本打平（0.712 vs 0.706，噪声级；
   typo 版有 4 条模型没答出类别，按答错算）。回头细看论文的错别字结论：
   它是用逻辑回归算"错别字数 → 正确率"的系数，p 值根本没过显著性线
   （GPT-4o 的 0.077、Mistral 的 0.113，都大于 0.05），论文自己也只说
   "观察到相关"。所以我的直接对照实验说明：**对强模型来说，几处拼写
   错误伤不了分类**。这是个诚实的负结果，也是这次复现我觉得
   最有价值的地方。

### 错别字实验为什么折腾了三版

第一版只改 25% 的单词，F1 纹丝不动（0.706 vs 0.705）；第二版加到
35% 还带保底，结果不降反升（0.729），明显不对；第三版推倒重写：
50% 的单词、用推文 id 当随机种子、严禁动首尾字母，三个跑法在四个
事件上全部小降，才拿到可信的负结果。教训：扰动强度不够的实验，
测出来的"鲁棒"是假的。

## 几个自己踩出来的坑

**1. 数据集官方页面好找，但 set2 要填表申请。**
"有公开数据集"和"能直接下到数据"是两码事。set1 直连下载，
set2 要填谷歌表单走人工审批，>= 天级周期。复现前一定要先确认
能不能拿到数据，别等代码写完才发现数据下不来。

**2. HumAID 类别分布两极分化严重。**
"伤亡"在加拿大野火里一条没有、"失踪寻人"在我选的 4 个事件里
整类缺席。看论文的 19 事件大平均不觉得，一旦裁到小样本，
类别缺席立刻成为问题。我最后选了"按切片实际存在的类别算宏 F1"，
这是唯一不误导人的算法，代价是和论文的整体数字不能严格对齐。

**3. 错别字实验必须用固定种子。**
人肉给几条推文加错别字，加哪条加几个全凭心情，别人复现不了。
我用推文 id 当随机种子：哪个词、改什么位置、怎么改（对调/删/重复）
全部确定，跑一百遍错得一模一样，这才算实验。

**4. glm 偶发超时，又不设超时就是无限挂起。**
前几个项目的教训直接沿用：每条调用 120 秒超时 + 2 次重试，
异常单条记 ERROR 不中断整体，重跑自动补漏。这次还加了 6 线程
并发，不然一千多条串行跑要等到天亮。

**5. 模型有时候不听话，会输出一长串解释而不是类别名。**
论文提示词已经写了 "mention only the category name"，GLM 大部分时候
照做，偶尔还是啰嗦（比如输出 "Caution and advice - because..."）。
我的处理：解析对不上 9 个类别名就带着原提示词追问一次，再不行
记 PARSE_FAIL 按答错算。追问这个动作论文没有，算我加的兜底。

## 和原论文差在哪

- 模型：原 6 个（3 闭源 + 3 开源）多 shot 全测；我 1 个 GLM，只测 0/3-shot
- 数据：原 19 事件 test 集全量（15,160 条）；我 set1 里 4 个事件 406 条
- 少样本示例：原从训练集挑且试了 1/3/5/10 四种数量；我只做 3-shot
- 语言特征分析：原 17 特征逻辑回归 + hashtag 位置实验；我没做回归，
  改成了更直接的"同文本 typo 对照实验"（论文只有相关性，没有这种对照）
- 部分样本来自 dev/train 补足（原只用 test 集）
- 宏 F1 口径：我按切片内实际存在的类别平均（MFP 缺席）

## 和前几篇的关系

ReAct 让智能体会用工具，AutoGen 让多智能体会协作，E-KELL 让答案有
知识图谱兜底，这篇补的是**最前面一环：灾情推文怎么识别、识别有什么坑**。
论文自己点名的三个弱点（洪水难、求助类难、错别字敏感）会直接变成
我后面系统设计时的加固清单。四篇拼起来，我的"知识增强的多智能体
灾害态势推理与辅助决策"就从数据入口到决策出口全串起来了。
