# E-KELL 复现笔记（知识图谱 + 大模型的应急决策支持）

> 复现论文：Enhancing Emergency Decision-making with Knowledge Graphs and Large Language Models
> （E-KELL，arXiv:2311.08732）
> 用到的模型：智谱 GLM-5.3-Flash（API 调用）
> 时间：2026年10月

## 这项目干了啥

一句话：把应急标准做成知识图谱，让大模型答题的时候只能照着图谱答，不许自己编。

论文慌的地方在于应急场景里大模型会一本正经地胡说。它举的例子我看完都惊了：
问丙烯化学式，两个大模型一个答 C3H8O 一个答 C3H4，正确答案是 C3H6。
考试答错也就扣几分，事故现场答错就出人命了。所以论文想了个笨但有效的办法——
先把标准法规整理成知识图谱，用户提问时先在图谱里检索，再把检索到的三元组
连同一句"只许用这里面的知识作答"一起塞给模型。模型想编都没有空间。

我照着复现了一条管线，分三步：
1. 建图：把标准条文喂给 GLM，抽成 (主体, 关系, 客体) 三元组，存成 kg.json
2. 查图：问题里抽关键词 → 图谱里捞相关三元组（还带一层邻域扩展）
3. 答题：三元组 + "不许用图谱以外的知识"一起给模型，生成答案

每一步都会打印，能看清答案是从哪几条三元组来的。应急决策里这条特别重要：
指挥员得知道"这句话的依据是什么"，不然出了事说不清。

## 关于数据集，说清楚

有同门问我"数据集太大复现不了怎么办"。这篇论文恰好没这个问题：
它压根没有训练集，它的"数据"就是应急标准法规的文本本身。
原论文用了 2 部法规 + 10 部标准（危化品方向），抽出来 2264 个三元组，
模型用的还是能本地跑的 ChatGLM-6B，全程没有训练这回事。

我的麻烦正好反过来：那些国标行标的全文我弄不到（正规渠道要买）。
所以我从论文附录里 E-KELL 自己引用的标准知识点出发——二氧化硫的沸点、丙烯的
化学式、泄漏隔离距离 500/1500/1600 米这些——再加上公开渠道能找到的应急常识，
自己整理成 3 份精简条文（corpus.txt，一共约 80 条），抽出来 165 个三元组。
规模只有原论文的零头，但知识口径一样，走的机制也一样。裁掉的每一处
我都列在下面"和原论文差在哪"里了，谁来查都查得出。

评测的数据集也是自己造的：按论文附录里的 10 个决策点（物资储备、现场指挥、
隔离疏散这些）出了 10 道中文题，让纯大模型和"大模型+图谱"各答一遍做对比。
题目答案都公开在仓库里，别人也能复现。

## 为什么没用 Neo4j 和 LlamaIndex

论文把图谱存图数据库、检索用向量库。我用 JSON 存图、用字符串匹配查图。
165 个三元组装 Neo4j 纯属杀鸡用牛刀；向量检索那步被我用"关键词命中 + 邻域扩展"
顶替了，效果糙一点，但对付这 10 道题够用，而且代码每一行都是自己的，
导师问到哪儿我都能讲明白。

## 怎么跑

```
# 装依赖（.venv 已有的话跳过）
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

# .env 里填智谱 API Key

# 1. 从语料建知识图谱（几分钟，生成 kg.json）
.venv\Scripts\python.exe build_kg.py

# 2. 单题问答，能看完整推理过程
.venv\Scripts\python.exe reason.py
.venv\Scripts\python.exe reason.py "你的问题"

# 3. 10 题对比评测（纯 LLM vs LLM+图谱，结果缓存 eval_answers.json）
.venv\Scripts\python.exe eval.py
```

## 文件一览

- `corpus.txt` 语料：3 份精简的危化品应急标准条文
- `build_kg.py` 建图脚本：GLM 抽三元组 → kg.json
- `kg.py` 图谱查询：投影/交集/并集/补集 + 关键词命中 + 邻域扩展
- `reason.py` 问答管线：抽关键词 → 查图 → 带证据作答
- `eval.py` 评测：10 题 × 2 方案，打分 + 客观要点核对
- `kg.json` 建好的图谱（165 个三元组）
- `eval_answers.json` 评测缓存

## 几个自己踩出来的坑

**1. 提示词里那句"不许用图谱以外的知识"是整个系统的命门。**
论文附录的模板里有这句。我第一次没加，模型就习惯性往外自由发挥；
加上之后完全变了样：检索不到就直说知识库里没有，一个字都不多编。
这句话就是"知识增强"和普通大模型的本质区别——前两篇 ReAct、AutoGen 的模型
可以自由发挥，这篇不行，这正是应急场景要的克制。

**2. 让模型抽三元组，格式必须下死命令。**
第一版让它自由发挥，输出一会儿带编号一会儿用顿号，解析代码天天崩。
改成"一行一个、竖线分隔"再给足示例才稳住。抽的时候它还会从一条条文里
抽出两条三元组（主体-配备-装备 和 装备-数量-数值），这其实是好事，
等于顺手把论文里手工做的属性层也抽出来了。

**3. 字符串检索会输给标点符号。**
第 6 题问"毒性中等、危害较小的区域"，图谱里的实体写作"毒性中等危害较小的区域"，
一个顿号之差就匹配不上，答案漏掉了整个防护等级部分。后来加了一步：把问题和
实体名都去掉标点再比对，才解决。论文用向量检索压根不用愁这个，我用字符串
匹配就得自己兜。

**4. 请不起消防专家评分，就用两招代替。**
主观分让另一个模型调用代评（有自己夸自己的嫌疑，分数看个趋势就行）；
客观部分不看谁脸色：每道题设 2-3 个标准要点关键词，直接查答案里在不在，
这个才是硬的。

## 测试记录

10 道题 × 2 方案，模型代评四维（1-10 分）+ 客观关键词核对，全跑完了：

| 方案 | 可理解 | 准确 | 简洁 | 指导 | 客观命中 |
|------|-------|------|------|------|---------|
| 纯 LLM | 9.0 | 8.4 | 8.7 | 8.8 | 10/28 |
| LLM+图谱 | 8.5 | 7.4 | 7.9 | 5.9 | 16/28 |

看到这个表我自己先愣了一下：模型代评四维全是纯 LLM 赢，是不是说明图谱白干了？
细看就明白了，两个指标说的是两码事：

**客观命中才是我真正关心的**——那是查"答案里有没有踩中标准里的关键点"，
纯 LLM 10 个、加图谱 16 个，图谱版多踩了六成。典型的是 Q1（物资储备）：
纯 LLM 答得头头是道但一条标准依据都没有（命中 1/3），图谱版三条全中又全对。
Q3（事故调查）也一样，纯 LLM 靠编，图谱版三条全中。

**模型代评低分全出在"指导性"上。** 我查了最低分的两题：
Q10（报告汇编）图上没三元组，程序老老实实回答"没有查到相关知识点，不编"——
写着"绝不编造"的约束起效了，但按"指导性"打分当然垫底（8/3/8/1）；
Q5（灭火）图谱版把条文碎片全列出来，杂货铺风格，也被扣了分。
还有一个细节：图谱里"灭火时严禁使用其他物质灭火"这种三元组，
原文有主语语境没问题，但抽成"灭火→禁止→其他物质"单拎出来就怪了——
三元组丢上下文的毛病，原论文也有，我算是亲身体会到了。

所以这轮评测教会我的不是"图谱没用"，而是：
模型代评会偏爱流畅自信的废话（纯 LLM 的答案基本是"标准官腔"+自己编细节），
事实核对才看得出来谁在编。而且我的图确实还小（165 个三元组），
覆盖不了的问题就只配拒答。这两个结论我都认，也写在这里不遮着。
（跑评测时还踩了坑：glm 偶发请求超时，没设超时会无限挂起，
后来设了 180 秒超时 + 失败续跑缓存，漏题自动补齐，代码里留了注释。）

## 和原论文差在哪

- 语料：原 12 份法规标准全文，我 3 份精简条文；图上 2264 vs 165 个三元组
- 检索：原 LlamaIndex 向量库，我字符串匹配 + 邻域扩展
- 推理：原论文会把问题自动拆成一阶逻辑表达式（投影/交集那些）再逐步查，
  我在 kg.py 里只实现了这四个查询函数，自动翻译那步没做
- 评测：原 19 位专家人工打分，我模型代评 + 客观关键词核对
- 界面：原有指挥中心 PC 端和一线 MR 端，我只有命令行

## 和前两篇的关系

ReAct 证明智能体会用工具，AutoGen 证明多智能体会开会，
这篇补上最后一块：知识从哪来、答案凭什么可信。
三篇拼一起就是"知识增强的多Agent灾害态势推理与辅助决策"的基本盘。
有意思的是论文自己也在展望里说下一步要引 agent 框架来补检索，
等于我沿着它的展望提前把拼图拼上了。
