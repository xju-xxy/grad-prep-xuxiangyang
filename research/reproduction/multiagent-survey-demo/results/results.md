# LLM 多智能体综述 可提取组件复现 结果

> 对应复现：multiagent-survey-demo（模型：智谱 GLM-4-Flash，2026年10月）
> 本目录另有全部打标记录 `predictions.json`（每条都能查到模型的判定依据和原始输出），
> 以及对比表 `comparison.csv` / `comparison.md`

## 做了啥

综述（arXiv:2402.01680）自己没实验，硬复现复现不出东西。我把它那套四维坐标系
（环境接口 / 人设 / 通信 / 能力获取）编码进 `schema.json`，写了个工具让 GLM
拿着坐标系去给一段系统描述打标签，每个维度给标签和依据。
然后自己整理了 12 个真实的多智能体系统（10 个综述点名的 + 2 个我自己的），
各写一段 2~3 句描述，逐个跑一遍，装成一张对比表。

12 个系统全部成功打标，没有失败。温度 0.1，模型 glm-4-flash。

## 对比表长什么样

主表在 `comparison.md`，每行一个系统，列是四个维度的标签。摘要一下：

| 维度 | 分布（12 个系统） |
|---|---|
| 环境接口 | 无环境 6，沙盒 5，物理 1 |
| 人设 | 人工预定义 10，模型生成 2 |
| 通信范式 | 合作 8，辩论 3，竞争 2（可多选，有重叠） |
| 通信结构 | 去中心化 6，分层 3，中心化 3，共享消息池 2（可多选） |
| 反馈来源 | 其他Agent 11，人类 6，环境 4，无 1（可多选） |
| 生长机制 | 记忆机制 10（只有它，别的都没沾） |

大面上讲得通：MetaGPT 判成"无环境 + 预定义角色 + 合作 + 共享消息池"，
跟综述把它当共享消息池标杆的说法对得上；CAMEL 判成"模型生成人设 + 去中心化"，
也准；RoCo 是唯一被判物理环境的，也是唯一多模态那条打 √ 的。

## 四个坑的褒贬核对

`comparison.md` 里右边四列就是坑的核对（√=这个系统触及/缓解了，×=没涉及）：

| 坑 | 有几个系统触及 |
|---|---|
| 多模态空白 | 1/12（只有 RoCo） |
| 幻觉级联 | 0/12 |
| 群体优化缺失 | 0/12 |
| 缺应急 benchmark | 0/12 |

这一栏基本是空的，我得如实说清楚为什么。不是这些系统真就没有一个跟幻觉、
跟 benchmark 沾边，而是我这个核对是让模型"只从你给的那段描述里找线索，
描述里没写就判 false"。而我写的这 12 段描述本来就只讲了架构，没写
"它怎么防幻觉""它用什么数据集评"。规则加描述一起，结果就是这一列几乎全是 ×。
换句话说这栏现在测的其实是"我的描述写得全不全"，不是系统本身。
要让它有信息量，得在每段描述后面补一句"这个系统声称能 X / 用 Y 数据集测过"。
这次先留着，当作一个已知的局限。

## 模型判得离谱的地方（如实记）

**1. 环境接口这一维，模型把"虚拟场景"一股脑当成沙盒。**

这条最明显。我给自己的 autogen-demo 写的描述里只说了"模拟一场县级应急指挥会议"，
模型就判成 Sandbox，理由原文是"模拟一场县级应急指挥会议，说明这是一个虚拟环境"。
crisis-sight 也一样，被判 Sandbox，理由里它自己都承认"描述中没有提及与真实物理
世界的交互，因此**推测**是在一个模拟环境中进行操作"。可这两个系统明明是关起门
纯文本讨论，按综述的定义该是 None。

ChatDev 那条更离谱，判 Sandbox 的理由是"使用聊天链进行角色之间的对话，
这表明 Agent 在一个虚拟环境中进行交互"。聊天链就是多轮文本对话，
哪来的沙盒。这一条我觉得是纯判错。

回头看，根源是综述里 Sandbox 的定义（"人造的可交互环境，比如代码解释器、游戏世界"）
里那个"可交互环境"太模糊。模型把"AI 在虚拟情境里活动"和"Agent 真的能操作一个
环境、拿到环境反馈"混成一回事了。这跟我在 disaster-survey-demo 撞到的
"识别 vs 态势评估"边界问题是同一类毛病：框架给的定义不够硬，落到硬判定就翻车。
区别是这次翻的方向是"偏沙盒"——模型宁可把没环境的往 Sandbox 上靠。

**2. 多智能体辩论被判成"模型生成人设"。**

Debate 那条，模型给人设判了 Model-Generated，理由是"让多个模型实例对同一个
问题各自给出答案"。可那只是同一个模型开几个实例，谈不上"生成角色"，
按综述的分类更像没有明确人设或者用固定提示。这一条我判断是模型把"多个实例"
误读成了"生成人格"。

**3. 反馈来源和生长机制这两个子面，模型有点无脑往上填。**

反馈来源里"其他Agent"给了 11/12，生长机制里"记忆机制"给了 10/12。
可我看依据，好几条是硬凑的。比如 ChatDev 判了"人类"反馈，理由是
"有教练式的指令引导"——那个教练指令其实是写死在提示词里的，不是人类中途介入，
按综述的定义算不到人类反馈头上。AutoGen 判"记忆机制"的理由是
"没有提到自我进化……但提到可以记忆和检索信息，这暗示了记忆机制的存在"——
它自己都说描述里没提，还是给填上了。这两个子面模型偏乐观，
"没明说也猜一个"，跟我提示词里写的"没明说就按最可能的情况猜"有关系。

## 三条示例判定（直接抄 predictions.json）

**MetaGPT（判得准的一条）**
- 环境：None / 人设：Pre-defined / 范式：合作 / 结构：共享消息池 / 反馈：无
- 依据（结构）："描述中提到 Agent 之间通过共享的消息池交换结构化文档，
  这表明它们是合作且使用共享消息池进行通信的。"

**RoCo（唯一物理环境 + 唯一多模态 √）**
- 环境：Physical / 人设：Pre-defined / 范式：合作 / 结构：去中心化
  / 反馈：环境 + 其他Agent / 机制：记忆机制 / 多模态空白：√
- 依据（环境）："在真实的物理环境里合作完成长程任务。"

**autogen-demo（我自己的系统，判偏了）**
- 环境被判成 Sandbox，依据："模拟一场县级应急指挥会议，说明这是一个虚拟环境，
  并非真实的物理世界。" —— 我的系统没有沙盒，这条是错的，但模型分不清。
- 其余判得还行：人设 Pre-defined / 范式 合作 / 结构 分层+共享消息池
  / 反馈 环境+其他Agent+人类 / 机制 记忆机制。

## 结论

- 四维坐标系能跑起来，12 个系统全部打上了标签，也确实把文献装进了抽屉：
  合作类（MetaGPT/ChatDev/CAMEL/AutoGen）、辩论类（Du et al./ChatEval）、
  竞争类（狼人杀/阿瓦隆）、具身类（RoCo）各自归位，看一眼表就知道谁在哪个格
- 人设和通信这两维判得最稳。人设 10 个都判 Pre-defined，跟事实吻合；
  通信范式和结构的多选也没乱来
- 环境接口最容易翻车，模型有把"虚拟/模拟/对话"一律往 Sandbox 上靠的倾向
- 四个坑的核对这一列这次信息量很有限，原因在规则和我的描述，不在系统本身
- 一个教训：这套框架当"整理的坐标系"很好用，当"自动打标的硬标尺"边界不够，
  尤其是 Sandbox / None 和 反馈来源这两处，得靠人复核
