# LLM 多智能体综述 复现笔记

> 复现论文：Large Language Model based Multi-Agents: A Survey of Progress and Challenges
> （Taicheng Guo、Xiuying Chen 等，IJCAI 2024 Survey Track，arXiv:2402.01680）
> 用到的模型：智谱 GLM-4-Flash（API 调用）
> 时间：2026年10月

## 这是一篇综述，怎么复现

前一篇综述（灾害管理那篇）我已经踩过一遍"综述没法复现"的坑了，这次倒是想得比较清楚。
系统论文有实验有数字，搭一遍比对指标就行；综述满篇是别人的工作，
你硬要"跑一遍"是跑不出东西的。

它的真贡献是那套四维分析框架。说白了就是四个抽屉：
每个 Agent 跟环境什么关系（沙盒/物理/没有）、人设从哪来（手写/模型生成/数据里挑）、
彼此怎么说话（合作/辩论/竞争，配分层/去中心化/中心化/共享消息池）、
能力怎么长起来（反馈来自环境/其他 Agent/人类/没有）。
拿这四把尺子去量任何一篇多智能体论文，基本都能塞进某个格子。

所以这次复现干的事就是：**把这套坐标系落成一个能跑的打标工具**。
把框架编码进 `schema.json`，写个脚本让 GLM 读一段系统描述，吐出四个维度的标签
和判定依据；再自己整理一批真实的系统，用这工具一个个打标，装成一张对比表。
这样"用四维坐标系把文献装抽屉"这件事就不是嘴上说说，是有张表能看的。

## 这个项目做了什么

两件事，都真跑了：

一是打标工具。`classify.py` 拿 `schema.json` 里的四维框架去读一段多智能体系统的
文字描述，输出结构化 JSON：每个维度给标签 + 依据，四个坑给个触及与否的核对。
模型是 GLM-4-Flash，温度 0.1。

二是评测梳理。`systems.json` 里我自己整理了 12 个真实系统，10 个是综述正文点名过的
（MetaGPT、ChatDev、CAMEL、AutoGen、多智能体辩论 Du et al.、ChatEval、
狼人杀、阿瓦隆、RoCo、虚拟政府应急响应 Xiao et al.），另外 2 个是我自己仓库里的
（autogen-demo、crisis-sight）。每个配一段 2~3 句简介，`eval.py` 把它们逐个
喂给打标工具，生成对比表，落到 `results/`。

## 怎么运行

```
# 装依赖（.venv 已有的话跳过）
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

# .env 里填智谱 API Key（格式：ZHIPUAI_API_KEY=你的key）

# 单条打标，看模型怎么判一个系统
.venv\Scripts\python.exe classify.py
.venv\Scripts\python.exe classify.py "你的系统描述文字"

# 跑全部 12 个系统，生成对比表（结果缓存，跑挂了重跑会跳过已完成条目）
.venv\Scripts\python.exe eval.py
```

## 核心思路

框架是死的，打标是活的，中间全靠提示词把 `schema.json` 翻译成一段模型能照着做的规则。
我在提示词里做了几件事：

一是把 schema 摊平成人话塞进去。四个维度的选项、每个选项的定义、四个坑的说明，
全写清楚，尤其通信和能力获取这两维还分了子面（范式/结构、反馈来源/生长机制），
得让模型知道哪几个是多选、哪几个是单选。

二是定死输出格式，只准输出一个 JSON 对象，字段名固定，单选的那个填字符串，
多选的填数组。程序这边再用正则把 ```` ```json ```` 外壳剥掉，
免得它包一层代码块导致解析崩。

三是专门留了句"没明说就按最可能的情况猜，但要在依据里承认是推测"。
我预感这条会让模型乱猜，果然后面反馈来源和记忆机制那两列它就填得偏乐观，
这算是提示词自己埋的一个坑（下面细说）。

## 测试记录

12 个系统全部打标成功，没有失败。标签分布：

- 环境接口：无环境 6，沙盒 5，物理 1
- 人设：人工预定义 10，模型生成 2
- 通信范式：合作 8，辩论 3，竞争 2
- 通信结构：去中心化 6，分层 3，中心化 3，共享消息池 2
- 反馈来源：其他Agent 11，人类 6，环境 4，无 1
- 生长机制：记忆机制 10

大面上讲得通。MetaGPT 判成"无环境 + 预定义角色 + 合作 + 共享消息池"，
跟综述把它当共享消息池标杆的说法对得上；CAMEL 判成"模型生成人设 + 去中心化"，
也准（它本来就是先让模型自己生成两个角色）；RoCo 是唯一被判物理环境的，
也是唯一多模态那条打 √ 的，符合它具身多机器人的定位。
竞争的狼人杀和阿瓦隆、辩论的 Du et al. 和 ChatEval 也都归对了格子。

## 踩过的最大的坑：模型把"虚拟场景"全当成沙盒

这条最典型。我给自己的 autogen-demo 写的描述里只有一句"模拟一场县级应急指挥会议"，
模型就判成 Sandbox，理由是"模拟一场县级应急指挥会议，说明这是一个虚拟环境"。
crisis-sight 也一样被判 Sandbox，而且它自己在依据里都写了"描述中没有提及与真实
物理世界的交互，因此**推测**是在一个模拟环境中进行操作"——它知道自己在猜，
还是往沙盒上靠。可这两个系统明明是关起门纯文本讨论，按综述定义该是 None。

ChatDev 那条更离谱。判 Sandbox 的理由是"使用聊天链进行角色之间的对话，
这表明 Agent 在一个虚拟环境中进行交互"。聊天链就是多轮文本对话，
哪来的沙盒，这条我觉得是纯判错。

回头想，根源是综述里 Sandbox 的定义（"人造的可交互环境，比如代码解释器、
游戏世界"）不够硬。模型把"AI 在虚拟情境里活动"和"Agent 真能操作一个环境、
拿到环境反馈"混成一回事了。这跟我在 disaster-survey-demo 撞到的
"识别 vs 态势评估"边界问题是同一类毛病：框架给的定义留白，落到硬判定就翻车。
区别是这次翻的方向一致——模型宁可把没环境的往 Sandbox 上靠。

教训：这套框架当"人整理文献的坐标系"很好用，当"模型自动打标的硬标尺"就差口气，
尤其是 Sandbox / None 这一对，得靠人复核。

## 还有两处判得不放心的地方

**一是辩论系统的人设。** 多智能体辩论（Du et al.）被判成人设 Model-Generated，
理由是"让多个模型实例对同一个问题各自给出答案"。可那只是同一个模型开几个实例，
谈不上"生成角色"，更像没有明确人设或者用固定提示。我感觉模型把"多个实例"
误读成了"生成人格"。

**二是反馈来源和生长机制那两列填得太满。** 反馈来源里"其他Agent"给了 11/12，
生长机制里"记忆机制"给了 10/12。翻依据发现好几条是硬凑：ChatDev 判了"人类"反馈，
理由是有"教练式指令引导"，可那指令是写死在提示词里的，不是人类中途介入，
按综述定义够不着人类反馈；AutoGen 判"记忆机制"的理由是"没有提到自我进化……
但提到可以记忆和检索信息，这暗示了记忆机制的存在"，它自己都说描述里没提还是给填了。
这跟我提示词里那句"没明说就猜一个"直接相关，是我自己埋的雷。

## 四个坑的核对为啥几乎全空

对比表右边四列是四个坑（多模态空白、幻觉级联、群体优化缺失、缺应急 benchmark）的
核对，结果几乎全是 ×，只有 RoCo 的多模态打了 √。这得说清楚不是哪些系统真就没救，
而是我这套核对本身有两个局限：一是提示词要求"只从你给的描述里找线索，描述没写就判 false"，
二是我写的 12 段描述只讲了架构，没写"它怎么防幻觉""用什么数据集评过"。
规则加描述一起，这列测的其实是我的描述写得全不全，不是系统本身。
要让它有信息量，得在描述里补上系统的自评线索。这次先留着当已知局限。

## 和原论文比还有哪些没做

- 综述没有下游实验，我做的"让模型按框架打标"是我自己加的用法，论文里没有，
  所以没有它的数字能对照
- 12 个系统只是综述点名作品的一小部分，样本很小
- 每个系统的描述是我手写的，带主观性，模型判得对不对没有 gold 标准，
  只能靠我人工复核，不像 disaster-survey-demo 那边有 gold 能算准确率
- 模型只有 glm-4-flash 一个，没换别的模型看一致性
- 综述提的"机制模型 + 决策模型解耦"等架构思路没碰

## 和我的研究方向的关系

我方向是知识增强的多 Agent 灾害态势推理。这篇是我课题的坐标系。
这次复现相当于把这套坐标系拿来量了一圈我自己的系统：

- 我的 autogen-demo 和 crisis-sight 都落在"人设 Pre-defined + 通信 合作 + 结构 分层"
  这个格子里，反馈来源标了"其他Agent + 记忆机制"，正好就是我课题设想的
  "混合通信 + 外部知识记忆"那个交叉点
- 两个自己的系统环境接口都被判成 Sandbox，其实是模型判错，但也提醒我：
  我现在的系统确实没有真正跟环境交互，全是文本来回。综述说多模态环境几乎空白，
  我这块也是空白，这既是短板也是后面对比实验的入口
- 四个坑里"缺应急 benchmark"这一条，正对着我另一个 crisis-bench 项目。
  这次核对全 × 也侧面说明：现有系统没一个把应急评测当回事，那个空位还在
- 竞争类的狼人杀、辩论类的 ChatEval 和我这种合作类的在表里分得很开，
  说明四维坐标确实能把不同范式的系统区分开，不是挤成一团
