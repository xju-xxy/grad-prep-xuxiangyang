# U-Net 复现笔记

> 复现论文：U-Net: Convolutional Networks for Biomedical Image Segmentation（MICCAI 2015，arXiv:1505.04597）
> 跑在什么地方：本机 CPU，PyTorch 2.13（没显卡，U-Net 小图小模型 CPU 也扛得住）
> 时间：2026年10月

## 这个项目做了什么

把 U-Net 从头写了一遍——左边编码器一路 double conv + 2x2 池化往下压，右边解码器一路
反卷积上采样，上采样之后把左边同尺寸的特征图 concat 回来（这就是论文里那根关键的跳跃连接），
最后 1x1 卷积输出单通道 logits，sigmoid 阈值 0.5 得到二值掩膜。损失用 BCE + Dice 各占一半，
训练集是我自己拿随机形状合成出来的 800 张 64x64 灰度图。

数据没去下 ISBI——那套数据要注册、体积也不小，而且我这次真正想弄清楚的是"跳跃连接在代码里
到底怎么接、接错了会怎样"，合成分割数据完全够用。合成数据另外还有个好处：真值是我自己画的，
绝对干净，能排除掉标注噪声这个干扰项。

## 怎么运行

这台机器的系统 python 3.14 里已经装好了 torch 2.13.0+cpu、numpy、matplotlib、pillow，
所以我是直接用系统 `python` 跑的，没有像前几个项目那样建 `.venv`。
要是换到没装的机器上，先建环境再装依赖：

```
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

然后三步：

```
python gen_data.py                  # 造数据，生成 data/train.npz 和 data/test.npz
python train.py --epochs 30         # 训练，每轮在测试集上算一次 Dice，存最优权重
python predict.py                   # 用最优权重算 Dice/IoU，导出对比图
```

训练脚本有几个参数可以调：`--epochs`、`--batch`、`--lr`、`--base`（通道基数，默认 16，
调大网络变大）。30 轮在这台机器上大概 15 分钟。

## 核心思路

这一层其实没什么玄学：浅层特征分辨率高但不知道"这是啥"，深层特征知道"这是啥"
但分辨率被池化压没了。分割要的是两者兼得，所以 U-Net 把编码器每一层的输出原封不动搬到
解码器的同一层，`torch.cat` 拼一下再卷积。代码里就是这四行：

```python
d4 = self.up4(b)
d4 = self.dec4(torch.cat([e4, d4], dim=1))   # e4 是编码器那半边的特征
```

我一开始还担心 concat 会不会通道对不上，后来发现只要上采样倍数是 2、输入又是 2 的幂，
每层的尺寸天然就对得齐，`dim=1` 拼通道就行。这也是为什么我老老实实用了 64x64，
要是用个 70x70，下采样到第三层奇数尺寸就尴尬了，得补零。论文里大图用 overlap-tile 也是
一个道理。

还有个选择：上采样我用了 `nn.ConvTranspose2d`（也就是论文正文说的反卷积/up-convolution），
没用双线性插值。笔记里我提过疑问，论文正文主要讲反卷积但没给两者的对照，
所以我也就跟着用了反卷积，没做消融，这点算没复现到位。

## 踩过的最大的坑

第一次跑 train.py 直接崩了，报错是这个：

```
RuntimeError: The size of tensor a (16) must match the size of tensor b (8) at non-singleton dimension 0
```

当时我盯着 "tensor a (16)" 想了半天，以为是模型里哪一层的通道数写错了，
把 enc/dec 的通道数来来回回数了三遍，都没问题。

后来才反应过来跟网络一点关系没有：我的测试集是 200 张，batch=16，最后一轮只装得下 8 张。
我在算验证 Dice 时写的是

```python
dice_sum += (2.0 * inter + 1.0) / (den + 1.0)   # 错
```

`dice_sum` 初始化成 Python 浮点 0.0，第一次加进去的是个长度 16 的向量，它就"变成"了向量；
第二次加到长度 8 的向量上，两个都是非标量，维度就对不上了。改成先 `.sum()` 成标量再累加，
问题消失。这个错误一点都不高级，但确实卡了我一阵——所以现在我看到"维度不匹配"的报错，
第一反应是先数 batch，而不是数通道。

第二个坑跟模型无关：predict.py 出的对比图里中文标题全变成了方框。matplotlib 默认的
DejaVu Sans 没有中文字形，得在代码里显式指定一个中文字体（我用了 `Microsoft YaHei`）。
顺手把 y 轴标签的精度从两位改成四位，不然 Dice 全都显示成 `1.00`，最差那张的 0.9978 也看不出来。

## 测试记录

跑法：30 轮、batch=16、lr=1e-3、base=16，训练 880.6 秒（14.68 分钟）。

实际发生的：第 1 轮测试集 Dice 就 0.9794，第 3 轮 0.9992，从第 7 轮往后基本都贴在 0.9998 以上。
第 16 轮验证 Dice 掉了一下（0.9997，比上轮低），第 30 轮也掉到 0.9996，但整体已经没什么空间了。
训练 loss 从 0.9988 一路降到 0.0036。

用第 28 轮存下来的权重在测试集上算最终指标：

| 指标 | 平均 | 中位 | 最低 | 最高 |
|------|------|------|------|------|
| Dice | 0.99998 | 1.00000 | 0.99777 | 1.00000 |
| IoU  | 0.99996 | 1.00000 | 0.99556 | 1.00000 |

像素准确率（把背景也算进去）0.999995。

这个数看着漂亮，但我得说实话：它说明不了模型有多强，只能说明我出的题太简单。
我自己合成的前景是纯色块、比背景亮一大截、边界干净、形状之间还不重叠，U-Net 这种结构
几乎不费劲就分开了。对比图里我自己挑出来最差的两张，也就是形状尖角上差了一两个像素。
所以这组数字真正的意义是"跑通了"：网络结构接对了、损失在正常下降、跳跃连接确实在用、
推理能出一致的掩膜。

## 和原论文比还有哪些没做

- 论文用的是 ISBI 2012 细胞分割和 EM 神经结构数据，我用的是自己造的合成数据，
  任务难度差了不止一个档次，两边的数字没法并列比较，我就没硬凑
- 论文的加权损失里有张权重图 w(x)，专门给细胞边界附近的像素加权；我只用了普通 BCE + Dice，
  没实现这张权重图
- 数据增强（弹性形变、随机翻转旋转、灰度扰动）论文花了大篇幅，我一张图都没做增强。
  现在想想合成数据确实也不需要，但这就少复现了一块
- overlap-tile 的重叠切块策略没做（我的图才 64x64，用不上）
- 论文那套"用上一张图的预测结果做平滑"的后处理也没做
- 上采样到底用反卷积还是双线性插值，论文没给对照，我也没做消融

## 和我的研究方向的关系

我方向是知识增强的多 Agent 灾害态势推理。U-Net 和主线不在一条线上，但有两处是能接上的。

一个是"跳跃连接"这个设计本身。ResNet 是相加、U-Net 是拼接，两篇放一起看，
我现在看别的网络里的各种融合结构，基本能一眼看出它想干什么、代价是什么。

另一个更实在：我这次最深的感受是，在这类小数据任务上，"损失怎么设计、数据有多难"
比"网络再堆深一层"影响大得多。灾害领域的数据也少、也极度不平衡，
这个体会以后做灾害相关的感知模块（比如从卫星图/现场图里分割出受灾区域）时估计会直接用上。
