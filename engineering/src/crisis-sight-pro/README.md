# CrisisSight Pro

这是我自己写的一个小系统，把研究方向（知识增强的多智能体灾害态势推理与辅助决策）落成一个能点、能看、能跑的 Web 页面。

前阵子已经做过一版 `src/crisis-sight`，用的是 Flask + 原生 HTML/CSS/JS。那版能跑，但界面是手搓的 CSS，动画和图表都很糙，加个新面板就得复制一堆样式。所以这一版我把前端整个翻新了：React + TypeScript + Tailwind 重写，图表交给 Recharts，动画交给 Framer Motion，推演逻辑干脆从后端搬到前端。旧版留着不动，当作对照组。

## 这系统干嘛的

你在输入台写一段灾情描述，选好灾害类型（地震、洪涝、台风这类，一共 10 类），点「开始推演」。接着页面会跑一条流水线：

情报官 → 研判官 → 决策官 → 审核官，四个角色各发言两轮，一共八段。

每段发言都是现场生成的，素材来自我内置的灾害知识库——每个灾种都有「特征 / 主要危害 / 应对要点 / 次生灾害 / 监测指标」五项。发言里会明确标出引用了知识库的哪几项，这就是课题里说的「知识增强」：先拿事实锚住，再往下推理。

八段跑完，下面出结果：一份四段式报告（态势概述 / 风险研判 / 分级行动建议 / 不确定性与盲点）、风险等级徽章，还有一些从推演数据里现算出来的图表。报告能一键复制，也能下载成 Markdown。

## 怎么跑起来

需要 Node 18 以上，我用的是 Node 24。

```bash
npm install
npm run dev
```

打开 <http://localhost:5173> 就行。

想打成静态包：

```bash
npm run build     # 产物在 dist/
npm run preview   # 本地预览打包结果
```

国内装依赖如果卡，可以走镜像：

```bash
npm install --registry=https://registry.npmmirror.com
```

## 技术栈

- Vite 5 + React 18 + TypeScript
- Tailwind CSS 3（没上 v4，v4 还在折腾配置，v3 稳）
- Framer Motion：入场动画、卡片折叠、抽屉
- Recharts：雷达图 / 柱状图 / 饼图
- lucide-react：全套图标，一个 emoji 都没用
- 没有后端，没有 API Key，推演全在浏览器里算

## 设计上的几个取舍

**为什么把引擎放前端。** 上一版引擎在 Python 里，跑之前得先起服务，评审或者同学想看还得配环境。这版直接把知识库和编排逻辑写成 TS，`npm run dev` 打开就能用，换台电脑也一样。代价是知识库要跟着前端一起打包，数据量大了会难看，但现在这点内容无所谓。

**为什么不用组件库。** shadcn、AntD 这些我都试过，PoC 起来是快，但风格很难统一，最后总有几个地方长得跟别处不一样，一眼就看得出是拼的。这套界面我干脆全用 Tailwind 手写，卡片圆角、边框透明度、hover 位移都走同一套写法，看起来才是一整块。麻烦是慢，但可控。

**推演为什么是确定性的。** 这里没有任何模型调用，风险分、五个维度、资源占比都是从「你写的描述 + 命中的知识库条目」按固定规则算出来的。同样输入永远同样输出，方便演示和复现，也不会因为网络抽风翻车。坏处是它不会说人话以外的花样，遇到描述里没提到的东西就按知识库的通用项走。

**用户写的那段描述是真被用了。** 风险打分和一个维度分，都靠扫描述里的关键词来调。所以你把「被困」「倒塌」这类词加进去，风险等级和图表是会变的——不是套模板给你看个好看的假数。

**视觉基调。** 底色是 #0B1220 这种深蓝黑，强调色用青蓝（#22D3EE）做主线，靛蓝和琥珀分别管研判和警示。整体是应急指挥大屏的路子：玻璃拟态面板、微弱的渐变光晕、状态点呼吸。数字全部走等宽字形，免得跳动。

## 已知不足和下一步

- 引擎是规则驱动的，说白了还是一套「关键词 + 模板」，离真正的推理差得远。下一步想接 DeepSeek 之类的接口，把知识库条目拼进提示词，做成可选的真实推理，同时保留现在这套规则兜底。
- 五个风险维度的权重是我拍的，没什么依据。想拿几份真实灾情通报调一调，或者让评审的同学帮我标一批数据。
- 语料只有 10 类灾种，每类就一条。真要用得往细里拆，比如地震分城市和山区两套，洪涝分流域和城市。
- 打包出来主包 700 多 KB，全塞一个 chunk 里了。Recharts 占大头，后面按需拆一下，把图表和报告面板做成懒加载。
- 移动端能看，但流水线那几张大卡片在小屏上还是嫌挤，得再收一收。
